# Kernel Agent 周报（2026-09-07—09-13）

本周在两个算子上对比了原版 Atrex Kernel Agent（AKA）与 Runtime 方案的优化效果和 Token 消耗。

- **FlashAttention：**原版 AKA 两次运行合计消耗 **1,397.722M Token**；Runtime `pool-3` 消耗 **1,155.654M Token，节约 17.3%**。Runtime 最终在 CUDA、Triton、CuteDSL 三条路线上的 Kernel 延迟均低于 AKA 两次运行中的最佳结果。
- **GDN：**原版 AKA 到第 48 个 Episode 首次取得 **186.799 µs**，累计消耗 **1,047.397M Token**；Runtime `pool-retained-3` 到第 3 个 Epoch 取得 **187.373 µs**，累计消耗 **263.347M Token，约节约 74.9%**。两者延迟相差 **0.31%**，因此目前是接近相同的优化效果，尚未严格追平 AKA。

FlashAttention 比较的是完整归档，GDN 比较的是首次达到相近性能的检查点；两项比较都不是跨系统同一 GPU Allocation 的配对复测。下周继续运行 GDN，检验能否稳定达到或超过 AKA 的 186.799 µs，并增加重复实验。

数据来源：[FlashAttention 消融报告](../experiments/production-qwen35-35b-fp8-atrex-gdn-4k256-20260814--flash-attention--l20n--claude/report.md)；GDN 的 `AKA_GDN_260904.md`、AKA Horizon `state.json` 和 Runtime `campaigns-shared_workspace-snapshot_20260912b` Registry。
