# 决策 0012：分离目标设计、实现状态与发布验收

[English](0012-documentation-status-and-release-gates.md) | 中文

## 状态

已接受。

## 背景

Runtime 正在渐进设计和实现。架构文字必然描述最终职责，而代码、自动化检查和部署验证的推进速度不同。设计文档中的无限定完成措辞可能让部分机制看起来已经生产就绪，也可能隐藏 Epoch 内分支记忆或 Failed Epoch Recovery 等产品语义缺口。

## 决策

文档划分三个独立权威来源：

1. `architecture.md` 与 `module-design.md` 描述目标，并在有帮助时标注当前实现。
2. `implementation-status.md` 是逐项说明已实现、部分实现、计划中、已推迟和需要部署验证工作的权威文档。
3. `testing-and-acceptance.md` 定义仓库证据和强制目标环境生产门禁。

配置、协议和运维参考只描述受支持接口，并显式列出运维缺口。每份英文项目文档都有持续维护的中文对应版本。完成声明必须链接当前证据；补齐指定机制的设计决策不能暗示无关门禁已经通过。

## 影响

功能变更必须同步更新实现矩阵、受影响设计/参考文档和验收证据。未实现能力应继续保持可见，不能用推测接口掩盖。仓库可以如实说明当前单节点基础已经较完整，但在全部强制门禁通过前禁止宣称生产就绪。
