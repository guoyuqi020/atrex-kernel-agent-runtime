## Repository verification

```bash
.venv/bin/python -m pytest -q
.venv/bin/ruff check src tests scripts
.venv/bin/mypy src
.venv/bin/python scripts/smoke-wheel-independence.py
sudo .venv/bin/python scripts/validate-linux-sandbox.py
(cd src/atrex-kernel-agent-core && ../../.venv/bin/python -m pytest -q)
(cd src/atrex-kernel-agent-core && ../../.venv/bin/ruff check src tests)
(cd src/atrex-kernel-agent-core && ../../.venv/bin/mypy src tests)
(cd src/atrex-kernel-agent-evolver && ../../.venv/bin/python -m pytest -q)
(cd src/atrex-kernel-agent-evolver && ../../.venv/bin/ruff check src tests)
(cd src/atrex-kernel-agent-evolver && ../../.venv/bin/mypy src tests)
(cd local-wiki && ../.venv/bin/python -m pytest -q)
(cd local-wiki && ../.venv/bin/ruff check src tests)
(cd local-wiki && ../.venv/bin/mypy src tests)
```

Test counts are intentionally not frozen in documentation; they change with every implementation
increment. Release evidence must capture the output of the commands above. The Lima reference
environment has exercised the Linux Sandbox boundary, shared-host DNS/egress and Runtime access,
virtiofs Worker-root preparation, and live Claude/Codex/QoderCLI connectivity. This evidence is
diagnostic and does not replace acceptance on the exact production image.

The Runtime suite covers durable state transitions and schema migration, fencing, append-only Bootstrap generations and partial recovery, common Core phases, full-repository Evolution, token reports, ordinary repeated Evaluate, same-allocation ABBA scheduling/batching/per-run evidence, durable Kernel/Agent/measurement/Bootstrap Run catalog queries and bounded source export, generation-scoped Gateway/Wiki capabilities and operation retention, Evidence visibility and raw-by-digest materialization, Wiki Outbox, lifecycle events, administration, readiness, retention, Git archive safety, exact commit provenance, application startup, and wheel independence.

## Live Agent Backend connectivity

The opt-in acceptance runner starts each selected Backend in a separate production
`BwrapSandboxLauncher` boundary with cgroup-v2 limits, mount/process isolation, a read-only resolver,
and shared host networking. It reuses the command generated by the checked-out Core
Backend Adapter and requires a successful terminal provider event from one minimal non-interactive
request:

```bash
sudo --preserve-env=PATH,CODEX_HOME,OPENAI_API_KEY,ANTHROPIC_AUTH_TOKEN,ANTHROPIC_API_KEY,QODER_PERSONAL_ACCESS_TOKEN \
  .venv/bin/python scripts/validate-agent-backends.py
```

Missing executables or credentials are reported as `skipped`; provider, proxy, Sandbox, and
terminal-event failures are `failed`. CI or release acceptance should add `--require-all`.
Backends can be selected independently:

```bash
sudo --preserve-env=PATH,CODEX_HOME \
  .venv/bin/python scripts/validate-agent-backends.py \
  --backend codex --require-all --json

sudo --preserve-env=PATH,QODER_PERSONAL_ACCESS_TOKEN \
  .venv/bin/python scripts/validate-agent-backends.py \
  --backend qodercli --require-all
```

The script discovers login state below the original non-root `SUDO_USER` home and mounts only the
selected Backend's credential paths read-only. Use repeatable `--credential BACKEND=PATH`,
`--executable BACKEND=PATH`, `--model BACKEND=MODEL`, and `--settings BACKEND=JSON` overrides when
the target image does not use standard locations. It never prints credential values.

For Lima, install the Runtime and the selected CLIs inside the Ubuntu guest, authenticate them as
the ordinary guest user, then invoke the same command with `sudo`. A macOS virtual environment or
host CLI binary cannot be reused inside Linux. Passing this check proves one live model request
through the reference Sandbox's direct network path; it does not prove the full Core/Evolver
workflow.

## Mandatory production evidence

Repository checks do not prove the following. A production release record must attach evidence for each item on the exact image and hardware:

| Gate | Acceptance condition |
| --- | --- |
| Package/source | Runtime wheel works without source checkout; approved Core/Evolver commits, trees, and sealed digests match release metadata. |
| Secrets/config | Unknown fields, weak/missing secrets, unsafe paths, missing inherited variables, and non-full commits fail before work starts. |
| Hostile-code isolation | On the target Linux image, prove Core/Evolver cannot read sibling Workspace/undeclared host-home paths, write outside `~/workspace`, survive process-tree termination, escape mount/process namespaces, or exceed CPU/memory/PID limits. Separately prove the declared shared-network behavior: public DNS/egress, loopback Runtime access, and reachable host/peer services are not restricted by Runtime. Network isolation is outside this boundary; command-contract unit tests do not satisfy the target-environment gate. |
| Process lifecycle | Timeout, cancellation, descendants, provider failure, and host termination leave no owned process and converge to an explicit recoverable state. |
| Gateway/GPU | Every authorized operation and denied operation works through the selected Core binding, Runtime Proxy, pinned Agate, driver, GPU, and Evaluation Contract. |
| Evolution semantics | Configured Challenger pool, concurrent same-start Trajectories, serial per-Trajectory Attempts, independent Kernel/Agent selection, same-DSL constraint, fresh sessions, rollback, and failure evidence reproduce under real providers. |
| Token accounting | All four provider-token buckets are accurate; missing or inconsistent reports fail closed at the intended model-request boundary. |
| Evidence/Wiki | Optimizer promoted history, Evolver all-branch history with Agent winners and exact Kernels, same-Trajectory current Attempts, complete measured Epoch outcomes, raw Session materialization, and live Wiki freeze-before-return match the real service. |
| Crash recovery | Forced termination at bootstrap, Challenger, Attempt, selection, Evidence publication, task lease, and Wiki lease points produces no duplicate authoritative outcome. |
| Operations/soak | Backup/restore, readiness failure, GC, rotation, disk pressure, cancellation, observability retention, and representative multi-DSL soak stay within agreed bounds. |

Each record must include release identity, wheel digest, Core/Evolver commit/tree/Artifact identities, image, OS/kernel, isolation policy when implemented, driver/GPU, Agate/Wiki/provider/model versions, exact commands, timestamps, sanitized logs, Registry backup, relevant Artifact digests, result, approver, and any waiver. A waiver must name owner, expiry, affected workloads, compensating control, and rollback trigger.
